## 2026-11-20

- **Tooling setup prompt.** Asked Claude to install four plugins from `claude-plugins-official` (claude-code-setup, code-review, pr-review-toolkit, commit-commands), but to show what each installs (skills, agents, hooks, MCP servers) before installing, and not to guess names. It checked each plugin's manifest first: none adds hooks or MCP servers; `/commit-push-pr` pre-allows `git push`.
- **Plan review caught two gaps before any code.**
  - Substring search would make "men" match "women's clothing", which breaks "only see products that have text matching". Changed to word-start matching (PLAN.md assumption 3).
  - Docker was not installed, so `docker compose up`, the reviewer's main run path, could not be tested.
- **Overrode an AI choice.** Claude installed Colima to avoid needing an admin password and licence acceptance. I preferred Docker Desktop (what most reviewers will have), installed it myself and had Claude remove Colima and its Homebrew docker CLI.
- **Recommendations kept as recommendations.** claude-code-setup suggested hooks (block private files, tests before commit, Prettier), a `/verify-acceptance` skill, and no new subagents or MCP servers. None applied yet.
- **Plan assumed Jest; NestJS 12 broke that.** While scaffolding, Claude found Nest 12 ships only as ES modules and that Nest's official starter moved to Vitest. It stopped and asked instead of forcing Jest into ESM mode; I chose Nest 12 + Vitest. CLAUDE.md and PLAN.md updated.
- **TypeScript 7 skipped.** TypeScript 7 is current, but the Nest 12 CLI pins `~6.0`, so the backend uses 6.0.
- **Audit finding judged, not auto-fixed.** With Jest installed, `npm audit` flagged a moderate issue in Jest's `glob`. It was dev-only, and `npm audit fix --force` would have downgraded Jest. It went away when Jest was replaced by Vitest; the backend now audits clean.
- **Checked the tests can fail.** All 68 backend tests passed first time, so Claude broke the code on purpose three times (substring search, no rating tie-break, no stale-cache fallback). Each break made the matching tests fail, which shows they guard real behaviour.
- **Smoke test against the real Fake Store** (outside the test suite): every endpoint answered as planned, and the enquiry email reached a temporary Mailpit container with reply-to set to the customer.
- **Frontend tests: 3 of 21 failed on the first run, all from the AI's own test queries.** The header's category nav is also a list of links, so queries like "the list" or "men's clothing link" matched twice. Fixed by scoping queries to `<main>`; no app code changed. Then broke the app on purpose twice (form shown without clicking Enquire, category not URL-encoded) and the tests caught both.
- **The browser check found what the tests could not.** Clicking through the running app (real backend, real Fake Store, Mailpit) showed tall product images stretching their tiles to uneven heights. Fixed in CSS with a square image box. All five acceptance criteria passed by hand, and the enquiry email arrived as plain text with reply-to set to the customer.
- **Open question raised by the AI: product images.** Product data goes only through the backend, but the `image` URLs Fake Store returns point at fakestoreapi.com, so the browser loads the pictures from there. Treated as static assets from the source's CDN, not API calls; to record in DECISIONS.md (a real source would serve images from our own S3/CloudFront).
- **Architecture rules now fail the lint.** ESLint enforces the CLAUDE.md boundaries: only `api/client.ts` may use `fetch`; no Fake Store URL in client code; only the module files may import the concrete Fake Store and SMTP classes; only `smtp-email-sender.ts` may import nodemailer; only `TopRatedPolicy` may rank by rating. Proved by linting a throwaway file full of violations: every rule fired, then the file was deleted.
- **Lint found real issues in AI-written code.** A timeout error dropped its original `cause`. Two `setState` calls inside effects caused extra renders: the search bar now remounts per URL term, and `useAsync` derives "loading" instead of setting it. Two promises were not handled (`navigate`, async form submit). Added a test for the search box resetting, and re-checked it in the browser.
- **AI mistake in its own lint config.** Overriding `languageOptions` after spreading `disableTypeChecked` re-enabled type-aware parsing for the config files, which then failed to parse. Fixed by merging the options.
- **Docker: one command, checked end to end.** `docker compose up --build` took about 3 minutes from a cold build: nginx (non-root) serves the app and proxies `/api`, the backend (non-root, healthcheck) is not published to the host, and Mailpit catches email. All five acceptance criteria re-checked in the browser on port 8080, with no Content-Security-Policy violations.
- **Caught a config trap before it shipped.** Copying the old `.env.example` to `.env` would have set `SMTP_HOST=localhost` inside Docker, so enquiry emails would fail. Fixed by commenting out every value in `.env.example` (the backend has working defaults) and letting Compose default `SMTP_HOST` to `mailpit`. Now no `.env` is needed at all.

About 20 other findings fixed, 5 consciously rejected or deferred; see `notes/ai-review.md`.
